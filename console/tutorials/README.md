# 教程编写指南（给维护同事）

这份文档教你**从零写出一个新教程**，不需要懂代码、也不需要懂这个项目怎么搭的。
看完你就能：填一张表 → 交给 AI → 上线一个新教程。

配套文件：

- `_TEMPLATE.md` —— 填写模板（你主要动它，复制一份来填）。
- `shipping-plan.js` —— 已上线教程的成品，想看「填满后长什么样」就看它。
- 本文件 `README.md` —— 你现在看的指南。

---

## 一、先搞懂三件事

### 1. 这个项目是什么

一个**仿亚马逊卖家后台（Seller Central）的演示网页**，纯练习用，所有操作都是假的，不连真账号。
它分两层：

- **Demo 层**：那个后台界面本身（库存列表、发货向导、各种弹窗）。这层你**不用碰**。
- **教程层**：盖在 Demo 上面的「新手引导」。你写的就是这一层。

### 2. 一个教程，用户看到的是什么

用户在教程库点开一个教程后，屏幕会变成「带你走一遍」的引导模式：

- **聚光灯**：把界面上某个控件圈亮，其它地方压暗，告诉用户"看这里"。
- **教练卡**：聚光灯旁边的小卡片，写着这一步要干什么。卡上有：
  - 小标题（chip，如「Step 1 · 选库存」）、大标题、正文、可选的浅色小贴士（tip）。
  - 按钮：`‹ Back` 回上一步；讲解步有 `Next ›`，最后一步是 `Finish ✓`。
- **右侧进度轨道**：把整个教程分成几个里程碑（如 开始 → 选库存 → 确认运输 → 完成），让用户知道走到哪了。
- 顶部有 `↻ Restart`（重来）和 `← All tutorials`（回到教程库）。

用户每一步的前进方式有两种，这点很重要，你填表时要为每步选一个：

- **点击式**：用户必须点那个被圈亮的控件，才会前进。用于"真的要动手做"的步骤。
- **讲解式**：用户读完，点卡片上的 `Next` 前进。用于"只是说明、不需要动手"的步骤。

### 3. 你的角色

你**不写代码**。你做的是：想清楚"这个教程要带用户走哪几步、每步圈哪里、说什么"，
用大白话填进模板表，交给 AI（Claude），AI 把它变成能跑的教程并自测。

---

## 二、整体流程（三步）

1. **填表**：复制 `_TEMPLATE.md`，重命名成你的教程名，照着填三块内容。
2. **交给 AI**：把填好的表发给 Claude，说一句"照这张表加一个新教程"。
3. **AI 生成并验证**：Claude 生成代码、接进网站、跑自检确认每一步都能正确圈到目标，然后告诉你结果。
   有要补的地方（比如你要圈的控件还没准备好），它会问你或直接补上。

就这么简单。难点不在工具，在**怎么把教程设计好**——这是第四节的重点。

## 三、动手填表（逐字段）

模板分三块。下面逐块讲，配示例。

### 第一块 · 教程基本信息

这决定教程库里那张卡片长什么样。照实填：

- **教程名**：用户看到的标题，如「修复滞留库存」。
- **分类**：归到哪一类，如 库存 / 发货 / 仓储。
- **难度标签**：如 核心流程 / 问题排查 / 进阶。
- **简介**：一句话说清这教程教什么。
- **预计时长**：如「4 分钟」。
- **英文 id**：内部文件名，留空让 AI 起也行。

### 第二块 · 进度轨道

把整个教程切成 3~6 个**里程碑**，按顺序列出来。
里程碑是给用户的"章节感"，不是每一步——通常几步合成一个里程碑。

例：开始 → 找到库存 → 设置数量 → 确认发货 → 完成。

### 第三块 · 步骤表（核心）

一行一步。每行填这几列：

| 列 | 怎么填 |
|---|---|
| 里程碑 | 这步归到第二块哪个里程碑 |
| 这步在哪个界面 / 什么状态 | 用大白话说，如「库存列表页，已勾选前两行」 |
| 高亮哪个控件 | 说人话，如「发送到 FBA 的按钮」；见文末锚点清单 |
| 卡片标题 | 一句话，动词开头，如「选择第一个商品」 |
| 卡片正文 | 1~2 句，说清楚要做什么 + 为什么 |
| 小贴士 | 可留空，放"注意点 / 易错点" |
| 前进方式 | 填「点击」或「Next」 |

锚点（高亮目标）怎么描述、有哪些现成的，见 **`_TEMPLATE.md` 文末的锚点清单**——那里最全。

## 四、把教程当成一条完整链路

最重要的一条，单独讲。**教程不是孤立的点按钮练习。** 真实业务里它是一条链路：
**外部输入 → 用户在过程中做决策 → 把结果交付到外部**。
教程要把这条链路讲完整，用户走完回到现实里才接得上。

对应教程的四个位置：

### 1. 开始前：要准备什么（外部输入）

动手之前，用户需要先备齐哪些现实材料 / 信息？写进**开场欢迎卡**。
例（发货计划）：真实的纸箱尺寸与重量、每箱装几件、承运商信息。
不交代准备，用户走到一半发现缺数据，只能中断。

### 2. 清晰的开始

第一步用居中欢迎卡（不圈控件）：一句话说清这个教程带他完成什么、
是安全沙盒不影响真账号，并把上面的"准备清单"放进来。

### 3. 过程中：帮用户做决策

流程里凡是要用户**做选择**的地方（运输方式、配置方案……），
别只说"点这个"，要讲清各选项的取舍，让他知道为什么这么选。
这是教程比"录屏"更有价值的地方。

### 4. 清晰的结束 + 结束后做什么（外部输出）

最后一步要让用户明确"做完了"。同时讲清**回到现实他还要做什么**——
教程产出的数据往往要交付到外部。写进**结束卡**（或结束前一步的 tip）。
例（发货计划）：把箱标贴到对应箱子、把含 PRO 号的 BOL 交给承运商、预约提货。
不讲后续，用户在 Demo 里点完"完成"，回到现实却不知道下一步。

一句话：**好教程有头有尾，且接得上现实**——开头告诉用户带什么来，过程帮他做判断，结尾告诉他拿什么走。

## 五、怎么写出一个好教程

工具谁都会用，差别在设计。下面是几条经验，照着做能少走弯路。

### 原则 1：一步只做一件事

不要一步里塞"勾选商品、再点操作、再选发送"。拆成三步，每步圈一个控件。
用户跟得上、不迷路，聚光灯也才圈得准。

### 原则 2：第一步用居中欢迎（并交代准备工作）

开场第一步不圈任何控件（高亮列写"不高亮"），居中显示一张欢迎卡：
一句话说清这个教程带他做什么、是安全沙盒不影响真账号，
并列出**开始前要准备什么**（外部输入，见第四节）。前进方式用 `Next`。

### 原则 3：正文说清"做什么 + 为什么"

- **做什么**：动作明确，把要点的控件名加粗。
  - ✓「点底部的 **Send to FBA**，用选中的商品开一个发货计划。」
  - ✗「我们继续下一步。」（没说点哪）
- **为什么**：能带一句"这步的意义"就带，用户学的是流程不是点按钮。
- 控制长度：正文 1~2 句。要补充的注意点放 tip，别堆进正文。

### 原则 4：点击式 vs 讲解式，选对

- 需要用户**真的操作**的（点按钮、勾选框）→ 用**点击式**，逼他动手，记得更牢。
- 只是**讲解或观察**的（介绍一个区域、解释一个概念）→ 用**讲解式（Next）**。
- 一个教程别全是 Next 干读，也别每步都强制点击到烦。以操作为主、讲解为辅。

### 原则 5：tip 用来放"坑"

tip 是浅色小字，最适合放：易错点、"为什么这么做"、专业提醒。
例：「箱标只能用于它自己的货件，千万别在不同目的地之间混用。」
没有就留空，不用硬凑。

### 原则 6：里程碑别太碎也别太粗

3~6 个为宜。太碎（每步一个里程碑）轨道就失去"章节感"；太粗（整个教程一个里程碑）用户没有进度感。

### 原则 7：从用户真实旅程出发

按"一个新人会怎么一步步操作"来排，不是按系统模块排。
从打开菜单开始，到看到成功结束，中间不跳步、不假设用户已经在某个页面。

## 六、常见坑

- **没讲准备和后续**：只教 Demo 里点哪几下，没说开始前要带什么、结束后回现实做什么。链路断了（见第四节）。
- **想圈的控件还没有锚点**：照常写人话，备注一句「需补锚点」，AI 会去加。别自己纠结。
- **想圈的界面 Demo 里还没有**（如滞留库存页）：这类要先建界面，工作量大，立项时单独和 AI 说清楚。
- **一步塞太多动作**：拆开（见原则 1）。
- **正文没说点哪**：每个点击式步骤，正文里一定要点名那个控件。
- **全程 Next 干读**：没有动手，用户记不住。多用点击式。
- **里程碑名太技术**：用业务语言（「确认运输」而不是「Step2 Confirmation」给用户看）。

## 七、一个迷你示例（从想法到表）

假设要写：**「取消一个发货计划」**（注意：这只是演示填法，相关界面不一定都已就绪）。

第一块：

- 教程名：取消发货计划｜分类：发货｜难度：核心流程
- 简介：找到一个进行中的发货计划，把它取消掉。｜时长：3 分钟

第二块（里程碑）：开始 → 找到计划 → 取消 → 完成

第三块（步骤表，节选）：

| 序 | 里程碑 | 界面/状态 | 高亮控件 | 标题 | 正文 | 前进 |
|---|---|---|---|---|---|---|
| 1 | 开始 | 居中欢迎 | 不高亮 | 取消一个发货计划 | 这个教程带你找到并取消一个进行中的发货计划。安全沙盒，不影响真账号。**动手前先确认**：这个计划还没发出、且确实要取消（已发出的不能在这里取消）。 | Next |
| 2 | 找到计划 | 在 Shipments 列表页 | 「Work on shipment」按钮（需补锚点） | 打开发货计划 | 在列表里找到要取消的计划，点 **Work on shipment** 进入。 | 点击 |
| 3 | 取消 | 计划详情页 | 取消按钮（需补锚点） | 取消这个计划 | 点 **Cancel shipment**，确认取消。 | 点击 |
| 4 | 完成 | 取消成功 | 不高亮 | 完成 | 计划已取消。**回到现实**：如果你已经打印过箱标或通知了承运商，记得同步取消那边的安排。 | Next |

注意第 1 步交代了"开始前准备"、第 4 步交代了"结束后做什么"——这就是第四节说的完整链路。填到这个程度，交给 AI 就够了。

把填好的 `.md` 发给 Claude，说一句：

> 照这张表加一个新教程。

它会：转成代码 → 接进网站 → 跑自检（确认每步都能圈到目标）→ 告诉你结果和需要你确认的点。

有疑问随时问它——它了解这个项目的全部结构，可以边问边改。
